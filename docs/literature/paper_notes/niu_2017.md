# A Study of Style in Machine Translation: Controlling the Formality of Machine Translation Output

## Citation

Xing Niu, Marianna Martindale, and Marine Carpuat. 2017. *A Study of Style in Machine Translation: Controlling the Formality of Machine Translation Output*. Proceedings of EMNLP 2017, pages 2814 to 2819.

Source file: `D17-1299.pdf`

## One-Sentence Summary

The paper introduces formality-sensitive machine translation, where a translation system reranks candidate translations to match a requested sentence-level formality score.

## Research Problem

Translation should preserve more than literal meaning. Formality conveys information about audience, setting, relationship, and communicative intent.

Standard MT systems produce one translation without an explicit mechanism for controlling whether it is formal, neutral, or informal. The authors study a setting where the desired target-language formality is given as an additional input.

## Main Research Questions

1. Can sentence-level formality be quantified reliably?
2. Can a formality score be incorporated into MT reranking?
3. Can one translation system generate outputs at different formality levels?
4. Can formality be changed without materially harming adequacy and fluency?

## Motivation

The paper distinguishes *what is said* from *how it is said*. Expressions with similar content can differ in formality and therefore suit different social situations.

The authors ultimately want MT systems to preserve source formality. However, this paper takes a narrower first step: the desired output formality is specified externally.

## Task Definition

Formality-Sensitive Machine Translation, abbreviated FSMT, receives:

1. a source-language sentence,
2. a desired target-language formality level.

The system returns a translation whose formality is as close as possible to the requested level.

## Dataset

### Language Pair

French to English.

### Parallel Corpora

- MultiUN, representing formal institutional language.
- OpenSubtitles2016, representing conversational language with broader stylistic variation and an overall informal tendency.

Each corpus contributes:

- approximately 100 million English training tokens,
- 2,500 tuning segments,
- 5,000 test segments.

The corpora are concatenated to create mixed-style train, tuning, and test data.

### Formality Evaluation Data

The paper evaluates candidate sentence-level formality models using 11,263 human-rated English sentences drawn from blogs, email, answers, and news.

### Additional Corpora for Formality Modelling

The formality models use:

- the ICWSM 2009 Spinn3r dataset for large-scale vector-space training,
- conversational corpora as informal data,
- Europarl as formal data.

## Formality Representation

### Lexical Formality

Each word receives a formality score derived from its relationship to known formal and informal seed words.

The paper compares:

- similarity-difference models,
- support vector machine distance,
- principal component subspaces,
- DENSIFIER-based subspaces,
- a unigram corpus baseline.

### Sentence-Level Formality

The sentence score is a weighted average of lexical scores. Words with stronger formal or informal values receive more weight, while neutral words contribute less.

### Best Intrinsic Model

DENSIFIER with LSA representations obtains the best reported sentence-level correlation:

```text
Spearman correlation = 0.664
```

The unigram baseline obtains 0.540.

## Model or Method

### Base MT System

A phrase-based Moses system.

### N-Best Reranking

The base system generates an n-best list of 1,000 translation hypotheses.

For a hypothesis `h` and requested formality level `l`, the formality feature is:

```text
|Formality(h) - l|
```

This feature is used together with standard translation-model features in a log-linear reranker.

### Training

During reranker training, the requested formality is set to the formality score of the reference translation.

### Test-Time Control

The user supplies the desired formality level.

The paper tests three representative levels:

```text
low = -0.4
neutral = 0.0
high = 0.4
```

## Evaluation Method

### Automatic Evaluation

Test examples are divided into informal, neutral, and formal bins based on the formality of the reference.

BLEU is calculated for each requested formality setting.

### Human Formality Evaluation

Fifteen volunteers compare low-formality and high-formality output pairs for 42 source sentences.

Annotators choose:

- which translation is more appropriate for a formal setting,
- or neither / difficult to decide.

### Human Quality Evaluation

Annotators separately score:

- fluency without seeing a reference,
- adequacy with a reference.

Each segment receives approximately seven judgments.

## Main Results

### Automatic Results

The best BLEU score in each reference-formality bin generally occurs when the requested formality matches that bin.

| Requested Setting | Informal Test | Neutral Test | Formal Test |
|---|---:|---:|---:|
| Baseline | 39.74 | 40.17 | 47.97 |
| Low | 40.27 | 39.65 | 47.76 |
| Neutral | 38.70 | 40.46 | 47.84 |
| High | 37.58 | 39.53 | 47.97 |

The result supports the claim that formality-aware selection can improve reference matching when the requested formality is appropriate.

### Human Formality Results

Of the 42 output pairs:

- 20 pairs were judged to have no clear formality difference.
- 21 pairs had a discernible difference.
- In all but one of those 21 pairs, the high-formality output was judged more formal.

This shows that the reranker can shift style when the n-best list contains suitable alternatives.

### Human Quality Results

Average normalized ratings:

| Output Type | Fluency | Adequacy |
|---|---:|---:|
| Informal | 0.75 | 0.65 |
| Formal | 0.70 | 0.64 |

The adequacy difference is minimal. Formal output is rated slightly less fluent, possibly because it sounds more stilted.

## Qualitative Findings

The system produces differences such as:

- *ran away* versus *escaped*,
- *anybody hurt?* versus *is someone wounded?*,
- shorter casual wording versus more syntactically complete wording.

The method also fails in predictable ways:

1. The n-best list may not contain a valid formality alternative.
2. Reranking may select a semantically worse candidate only because its lexical formality score is closer to the requested level.
3. Lexical scoring can miss idiomatic formality. The words in *how do you do?* are not individually highly formal, but the expression is conventionally formal.
4. The model may delete or add content to satisfy the score.

## Strengths

1. Establishes formality as a first-class MT objective.
2. Models formality on a continuous scale rather than only a binary label.
3. Separates formality control from the base MT system through reranking.
4. Uses both automatic and human evaluation.
5. Explicitly evaluates adequacy and fluency to detect style-related damage.
6. Demonstrates that stylistic matching can improve reference-based evaluation.

## Limitations

1. Desired formality is supplied rather than inferred or preserved from the source.
2. The formality model is mainly lexical and misses idioms, syntax, discourse, and cultural conventions.
3. Reranking cannot generate a style variant absent from the n-best list.
4. BLEU cannot distinguish a valid style rewrite from a translation error.
5. Evaluation is French to English only.
6. Formality is treated as a single scalar, which may collapse politeness, register, social distance, institutional tone, and other dimensions.
7. The paper does not use conversational context or speaker-role information.
8. Human evaluation is relatively small.
9. Formal output can sound less natural even when adequate.

## Assumptions

- The desired target formality level is known.
- A sentence-level scalar is an adequate representation of formality.
- Lexical evidence is sufficient to rank useful candidate differences.
- The base MT system produces stylistically diverse candidates.

## Relevance to My Project

The paper supports two important distinctions:

1. Semantic adequacy and pragmatic style must be evaluated separately.
2. Formality is not identical to politeness.

For the proposed benchmark, this suggests separate fields such as:

```text
politeness_level
formality_level
speaker_relationship
speech_act
stance
```

It also supports a reranking experiment where multiple candidate translations are scored for pragmatic preservation.

## Methods I Can Reuse

1. Treat pragmatic properties as independent evaluation dimensions.
2. Use a score to rerank multiple valid translation candidates.
3. Evaluate style control and meaning preservation separately.
4. Include a human comparison between two translations of the same source.
5. Track whether a requested pragmatic shift introduces semantic errors.
6. Use continuous ratings where categorical labels are too coarse.

## Methods I Should Not Copy Directly

1. Do not define all pragmatic variation using a lexical formality score.
2. Do not assume a single scalar covers Indian social meaning.
3. Do not rely on n-best candidates from an older phrase-based system.
4. Do not infer success from BLEU alone.
5. Do not combine formality and politeness into one annotation field.

## Questions Raised by the Paper

1. Can source formality be inferred reliably in Indian dialogue?
2. Should formality be ordinal, categorical, or continuous?
3. How should cultural differences in formality be represented across languages?
4. Can a model preserve teasing or warmth while increasing formality?
5. How should evaluation handle multiple socially valid translations?
6. Can modern LLM generation replace n-best reranking with constrained candidate generation?

## Final Takeaway

The paper demonstrates that formality can be scored and used to control translation output, but lexical formality is only one component of pragmatic meaning. The proposed research should retain the paper's separation of style and adequacy while using richer, context-grounded pragmatic annotations.
